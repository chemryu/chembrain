## Bounded delivery recommendation

Build a separate install-free **Paper Workbench HTML** beside the updated **Chembrain HTML**, sharing trusted structure/contract code but using a separate entry and private workspace. Browser-side PDF selection/viewing, text-assisted candidates, editable chemical/route forms and a checked v1 JSON export can meet this request without Python installation, institutional credentials or AI API keys. A local Python review server adds installation and lifecycle friction and is not necessary for this bounded workflow.

The first version is a source-assisted curation program, not automatic exact optical chemical structure recognition. The UI and delivery instructions must state that PDF drawings require source checking and encoded SMILES; parser-valid SMILES are not proof of correct paper identity, stereochemistry, atom mapping or reaction feasibility. Do not call keyword candidates extracted structures or automatically mark them reviewed. Do not guess drawn intermediates, bonds, stereocenters, reagents, stage order, yields or missing route edges.

## Completion criteria

1. **Independent program and private input.** Workbench opens separately, starts empty or with an explicitly imported fact package, and reads a user-selected local PDF entirely in the browser. PDF rendering/text extraction and RDKit are bundled for supported current Chrome/Edge; no CDN, model API, publisher request or upload is needed. Enforce bounded file/page/record sizes, useful failures and recoverable cancellation/reselection. PDFs and page previews stay in memory/private work; avoid putting original PDF bytes in localStorage, compact exports, build inputs, CI artifacts or records. A restored workspace must not silently pair locators with another selected PDF; use a document digest/reselection check. Main and SI may share a DOI but retain distinguishable document/page/locator evidence.
2. **Identity review before promotion.** Show DOI candidates, allow a user-confirmed article DOI and authors, and do not choose the first reference DOI as article identity. Readable page preview plus private text/SMILES candidates helps the user verify the source. No source prose is copied into public notes. PDF text and instructions are untrusted data. Scanned/drawing-only pages get an honest no-text/no-automatic-structure explanation.
3. **Explicit chemical records.** Enter/correct name, paper-local label, kind and stereochemical SMILES with a live drawing. Validate with pinned RDKit, canonicalize isomerically and derive supported formula/mass/identity descriptors from the graph. Distinguish unknown from invalid SMILES. Preserve explicit stereo, charge, isotopes and multifragment/salt representations; expose unresolved stereochemistry for source review. Do not invent descriptor values if the browser engine lacks an API. Changing SMILES invalidates stale derived fields and source confirmation. Unknown paper intermediates can remain explicit unknowns and cannot become verified structure facts merely by saving.
4. **Paper-scoped identity and existing IDs.** New paper-numbered compounds use deterministic DOI/document-scope plus local-label IDs; `compound 4` from different papers must not alias by name. Stable labels/IDs survive save/reload and repeated export. Importing an existing normalized package for correction preserves its existing IDs and links, enabling precise updates to the sample intermediates. Known exact structures can share graph identity only with verified descriptor equality; do not collapse salts/parents, stereoisomers or unresolved stereo by similar names/formulas. Surface collisions instead of silently relinking a different chemical.
5. **Recorded routes only.** Add/edit a reaction by selecting explicit reactant and product chemical IDs. Targets express route membership, never an inferred transformation. Add stage-specific solution/solvent/solute records and reported time/temperature/amount/concentration/yield, retaining null for unreported values. Each transferable reaction needs confirmed paper DOI evidence, a 1-based PDF page and a meaningful locator. Show a route preview of the exact records, preserving branches and disconnected fragments. Deleting/changing a chemical or solution must reject or explicitly repair dangling references. No route is invented from article order, label number or textual co-occurrence.
6. **Review and compact export.** Before download, show counts of papers, chemicals, encoded/unencoded structures, reactions, solutions and unresolved review items. Validate every nested row/reference and SMILES at export, not only during editing. A changed row cannot retain stale confirmation. Export only the strict existing v1 allowlist; papers contain exactly ID/DOI/authors. No PDF, excerpts, filenames/private filesystem paths, page images, raw candidates or source-document payload is included. Any draft export is explicitly labelled draft; source review is never conflated with software QA or automatic chemical verification. Restore/export data errors leave the previous working state usable.
7. **Reliable main-app receiving path.** Main import previews or reports actual additions, retained rows, blank-structure upgrades and conflicts, including chemical counts. Corrected existing missing structures must be transferable without overwriting user structures, names, aliases, notes, reactions or solutions. Matching must use stable IDs plus compatible identity context, not names alone. Conflicts in non-null structures or identity are visible and are not silently accepted. A user explicitly applies the proposed missing-field enrichment; it is not an automatic load-time merge-precedence change. Before changing an existing saved library, save and verify exact original primary-storage bytes to a unique private backup. Validate the full proposed library first; backup/storage failures preserve the original working bytes and UI. Re-import is idempotent; all foreign keys/DOI deduplication and prior edited-data precedence remain coherent. Fresh first imports still receive the incoming user's library instead of starter defaults.
8. **Separate local workspace and resilient persistence.** Workbench save/restore is clearly private and distinct from the main-import compact package; no private workspace is presented as a GitHub upload file. Reload, imported workspace failure and browser storage/quota failure have useful recovery and preserve previous data. Explicit JSON backups remain available; file location/browser profile limitations are documented. Do not promise cross-device or Box synchronization.
9. **Deliverable and review truth.** Produce both HTML files with same exact source SHA, hashes, dependency notices and concise instructions: open Workbench → select paper → verify/encode compounds → link steps → export facts → main Import/apply structure additions. Journal download scheduling is unchanged. Known Pages403/history/Public limits remain separate from downloadable-program success; no website-live claim, main merge, visibility/history change, user-PC installation, Box write or background automation.
