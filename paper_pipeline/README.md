# Separate paper processor

The web library never downloads or stores PDFs. This Python program collects public bibliography by journal, archives only explicitly licensed supported OA PDFs, and creates local review candidates. It uses no model API keys or institutional cookies. JACS is enabled; edit `journals.json` to add journal ISSNs. ACS article PDFs are the supported automatic resolver; other publishers remain DOI-only or accept locally supplied PDFs. It does not promise all OA PDFs.

```sh
python -m paper_pipeline ingest path/to/paper.pdf --work-dir /path/outside/site/review
python -m paper_pipeline export --curated reviewed-package.json --out library.json
python -m paper_pipeline anchor --config paper_pipeline/journals.json --work-dir /path/outside/site/archive --out library.json
python -m paper_pipeline weekly --work-dir /path/outside/site/archive --out library.json
```

Install `paper_pipeline/requirements.txt` for the source processor; its trusted HTTP/chemistry modules live in this repository. The browser app needs no Python. Uploaded multi-article PDFs may contain unrelated DOIs: `charest2005.pdf` contains both an adjacent article DOI and `10.1126/science.1109755`; review identity rather than picking the first match. Use `--doi` only after checking the relevant article.

Candidates are not reaction records. A human encodes scheme participants, stereochemistry, authors, stage-specific solvents/solutes and evidence into the portable v1 tables. Missing amounts/concentrations/SMILES stay null. Scheme OCR and automatic exact structure extraction are not implemented. `examples/total-synthesis.json` is a draft curated starter from the supplied main papers; SI/procedures and complex structures still need review. Salt isolates and multi-step yields are recorded as notes, not silently treated as free-base/single-step results.

Only `papers`, `chemicals`, `solutions`, and `reactions` enter the exported package. Papers deduplicate by canonical DOI; known structures by canonical isomeric SMILES/InChIKey; unknown numbered intermediates remain namespaced to their paper. No PDF text, figures, binary payloads or review candidates may be embedded. The web app validates imports, keeps existing edits, and exports compact backups.

The optional GitHub weekly workflow is scheduled for Monday 15:00 UTC (09:00 CST / 10:00 CDT). GitHub only activates scheduled workflows from its default branch: the schedule is not active merely because this feature branch was pushed. No automatic merge/default-branch change was made. Alternatively install a weekly task locally with `scripts/install_paper_schedule.ps1`. Raw archives are not published to Pages. Public bibliography updates may be published with the site; draft reaction candidates are never auto-promoted. Metadata pagination/checkpoints and PDF completion are separate. Known supported PDF work is saved in a bounded private `pending.json` before discovery advances: at most 2,000 entries / 8 MB, with at most 32 KB of public source identity/license/link metadata per entry. Queue saturation retains the current metadata page for retry. Each run attempts at most 10 pending items, including failed metadata refreshes, downloads or review creation; deferred and failed work remains queued even after its publication date leaves the discovery overlap. Old pending downloads refresh the DOI through public Crossref and recheck journal identity, current matching OA license/version and trusted PDF route; revoked, expired, unverified or mismatched evidence never authorizes a download. Verified files are reused, and a failed review-creation stage retries the saved PDF locally. Reports distinguish `metadata_complete`, `downloads_complete`, attempted/saved/reused/reviewed counts, pending, deferred and OA-unverified outcomes. The metadata checkpoint may advance while pending downloads remain; a successful metadata crawl does not claim all PDFs were archived. Preserve the work directory (including pending/checkpoint files) across runs; a disposable cache alone does not guarantee durable archival storage. A page-bound or provider failure retains the metadata checkpoint and reports a partial collection; late-indexed older papers can require manual backfill. This is weekly bounded discovery, not a guarantee of exhaustive coverage. The main app imports updates while preserving browser edits; it has no cross-device account sync.

The processor atomically replaces the validated normalized output before saving **any** advancing metadata cursor or completed-window checkpoint. Output failure leaves existing progress and the old package unchanged. If the later checkpoint save fails, the newly saved bibliography remains available and a retry safely replays older progress without duplicate DOI records. PDF pending work stays independent of that metadata publication boundary.

Before its first provider request, `weekly` calls the same preparation used by the explicit `anchor` command. A journal with no usable prior progress gains only its original start/end dates, initial cursor, zero processed count and crawl-start timestamp. That nonadvancing anchor survives a failed first output and a retry weeks later; existing valid progress is retained, and malformed progress fails closed rather than silently restarting with a newer date window. Initial discovery uses the prior fourteen days; subsequent windows start fourteen days before the saved checkpoint. This fixed checkpoint lookback preserves the same start date on delayed retries, including a recent checkpoint followed by output failure. A resumed page preserves its original end date as well. Keep these files to recover that original discovery window.

The CI path restores public DOI retry/checkpoint metadata from `build/paper-state`, prepares and saves nonadvancing anchors against the already-published feed **before** discovery, then publishes the normalized feed before saving advanced progress. The state save checks the origin-acknowledged feed commit and exact library digest; a failed feed push cannot advance durable discovery state. This retains replay/deferred work when an Actions cache is evicted. PDF bytes and review candidates remain outside that branch and outside Pages; their Actions cache is best effort, not permanent document storage. Run the local processor against a persistent private directory to retain a long-term PDF archive. The reviewed dispatcher artifact in `docs/weekly-dispatcher.yml` is not installed or activated.
