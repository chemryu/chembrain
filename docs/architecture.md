# 구조와 확장 지점

## 현재 구현

React / TypeScript 화면이 FastAPI JSON API를 사용합니다. 개발 시 Vite가 `/api`를 프록시하고, 배포 빌드는 FastAPI가 직접 제공합니다. API는 `server/app.py`, 입력 스키마는 `server/models.py`, 저장 계층은 `server/store.py`, 역방향 경로 탐색은 `server/routes.py`에 있습니다.

첫 버전은 설치할 별도 서비스가 없는 SQLite를 사용합니다. 분자·반응·근거를 고유 ID로 연결하며 JSON 기록을 트랜잭션으로 저장합니다. 팀 사용·동시 편집 단계에서는 PostgreSQL과 관계형 제약조건·마이그레이션을 도입하는 것이 다음 단계입니다. 벡터 검색이 필요해지면 pgvector를 붙일 수 있습니다.

## 자료 → 반응

1. PDF / UTF-8 Markdown / 텍스트를 업로드합니다. 원본은 앱이 생성한 이름으로 저장합니다.
2. PyMuPDF로 페이지별 텍스트를 추출합니다. 반응·촉매·수율 등 키워드가 있는 단락을 후보로 표시합니다.
3. 사람이 분자와 조건을 입력하고 원문 인용을 선택합니다. 인용은 지정 페이지에 실제 존재해야 합니다 (공백 차이는 허용).
4. 검토 완료 기록은 한 개 이상의 인용이 필요합니다. 이 상태는 **입력한 기록의 검토 상태**이며 실험의 재현성 검증 상태가 아닙니다.

조건은 명칭과 단위를 포함한 문자열로 보존합니다. 예: `전위·기준전극: 1.2 V vs Ag/AgCl`. 단위 환산·온도별 필터·수치 비교가 필요해지면 원문 값과 정규화된 값·단위를 함께 저장하는 별도 스키마를 추가하세요.

## 구조와 탐색

분자는 RDKit canonical isomeric SMILES + InChIKey로 식별합니다. 염·혼합물·양성자화 상태·호변이성질체는 자동으로 같은 분자로 합치지 않습니다. 화학 구조를 수동 검토할 여지를 남깁니다.

데모에 사용된 구조를 실제 자료에서 재사용할 수 있습니다. 같은 구조를 직접 등록하면 데모 분자 항목을 실제 입력으로 전환합니다. 실제 원문 근거로 반응을 등록할 때 참조된 데모 분자도 재사용하되, 예시 재고 정보와 메모는 제거하고 확보 상태를 미확인으로 바꿉니다. 데모 원문을 근거로 삼은 반응은 계속 데모로 표시합니다.

분자와 반응은 별도 노드입니다. 경로는 생성물에서 출발물질로 거슬러 올라가며 모든 반응물 가지를 포함합니다. 순환을 막고, 가지를 합한 총 반응 수에 최대 단계 제한을 적용합니다. 후보는 확보 상태 미확인 분자 수, 반응 수 순으로 정렬합니다. 탐색은 응답 시간을 위해 최대 3,000회 노드 확장, 반응당 최대 300개 조합, 노드별 최대 80개 후보로 제한합니다. 모든 경로를 열거하는 최적화 알고리즘은 아닙니다. 공유 중간체의 실제 물질 수지, 당량, 보호기·관능기 호환성, 반응 순서의 실험 적합성은 계산하지 않습니다.

현재 구매 가능 여부는 사용자 입력입니다. 실시간 공급사 조회·가격·위험성/장비 적합성 평가는 구현하지 않았습니다.

## 다음 구현 순서

1. 사용자가 제공한 논문과 SI로 실제 추출 실패 패턴 수집.
2. DOI·논문/실험 ID·조건별 원문 범위를 구조화하고 검토 이력 추가.
3. 구조 편집기(Ketcher), 그림 인식, OCR을 단계별 연결.
4. 선택 가능한 LLM 추출 어댑터: JSON 스키마와 원문 범위를 반환하고 사람 검토를 거침.
5. 팀 권한·PostgreSQL·백업과 자료 버전 관리, 필요 시 의미 검색 추가.

원문 업로드는 외부 서비스 전송 없이 처리됩니다. 로컬 단일 사용자 앱으로 서버는 loopback에 바인딩합니다.
